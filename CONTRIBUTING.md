# Contributing

Start with [development](docs/development.md) and [architecture](docs/architecture.md). Open an issue for substantial product or adapter changes, then use a focused branch and pull request. Keep installation examples generic and avoid personal server addresses, usernames, mount paths, screenshots or credentials.

Run type checks, lint/format, tests, production build and relevant browser/container checks. Include evidence for actual API capabilities and distinguish fixture tests from live service tests. Don't claim new browsers/architectures without verifying them. Public docs must describe implemented behavior; planned integrations belong in the roadmap.

Contributions are licensed under MIT. Record upstream URLs, exact commits, copied code/assets and licenses before reusing them; preserve compatible notices. Do not copy GPL/AGPL implementation into the MIT application without discussing the resulting licensing requirements. API interoperability with independent services is preferred.

Use fictional data in fixtures and review screenshots. Report security issues privately via [SECURITY.md](SECURITY.md), not a public issue containing sensitive detail.
