## Adapter evidence

All integrations are **fixture-tested**, not live-tested. Fixtures are hand-authored fictional minimal responses based on the official APIs and inspected upstream models/routes listed in [integrations](integrations.md). Tests validate account-bound credential headers, normalized identities/progress and pagination. They do not exercise real ebook/media codecs, upstream UI sessions, permission configurations or version-specific route behavior.

Handoff URLs are constructed and validated in tests. Actual resume remains source-owned and may require source login. No SelfLib playback, downloads, filesystem access, shell launch, or progress writeback exists.

## Resource measurements and estimates

Measured on the clean native production smoke install, with **16 fictional items and no cached source covers**:

| Measurement                            | Observed                                                                                                                         |
| -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| Node RSS after setup                   | About 67.5 MiB (70,782,976 bytes), sampled through `process.memoryUsage()` from the production child; not whole-container memory |
| SQLite after graceful stop             | 114,688 bytes                                                                                                                    |
| Runtime npm dependencies on disk       | About 15 MiB                                                                                                                     |
| Compiled output including maps         | About 280 KiB                                                                                                                    |
| Browser JavaScript / CSS, uncompressed | 27,026 / 34,066 bytes; no mandatory font download                                                                                |

These numbers are not large-library or homelab load tests. Reserve **256–768 MiB RAM** and roughly one available CPU core during sync/build as an initial estimate; Compose limits runtime to 768 MiB / one CPU. Password scrypt briefly uses additional memory/CPU. Metadata staging is bounded to 10,000 items per source; descriptions can make staging much larger than the demo. Synchronous transactions/password work can pause requests in this single-owner design.

Artwork is globally capped at 64 MiB, 512 KiB per image and 200 uncached attempts per sync. Metadata has 10-source/10,000-item-per-source bounds but no fixed SQLite file-size cap. SQLite/FTS duplicates some text; at 10,000 items with average 2 KiB descriptions, plan roughly 50–150 MiB metadata/index space **as an estimate**, plus artwork, WAL and backups. Very long descriptions and 10 sources increase that. Downloaded cover size/source latency dominate first sync. Requests time out after 10 seconds; metadata sync retries one transient failed page and stops at a two-minute budget, retaining the old complete catalog on failure.

Outstanding measurements: real-source initial/incremental sync at 1k/10k items, peak process/container RSS during catalog commit, image-build size, iOS rendering and battery impact, and real-source handoff/version compatibility. Walkable 3D and embedded playback would require separate browser/resource benchmarks.
